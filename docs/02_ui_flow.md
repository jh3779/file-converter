# 02. UI Flow — 사용자 경로 · 화면 목록

> 인터뷰 영역 5 정리 · 상태: draft

## 화면 목록 (SCR-*)
| ID | 화면 | 목적 | 주요 상태 |
|----|------|------|-----------|
| SCR-001 | 메인 (원스크린 드롭존) | 파일 추가 → 포맷 선택 → 변환 시작까지 한 화면에서 완결 | empty(드롭존만) / list(파일 목록) / converting(진행 중) |
| SCR-002 | 변환 결과 요약 | 일괄 변환 완료 후 성공/실패 건수·사유 표시, 결과 폴더 열기 | all-success / partial-fail / all-fail |
| SCR-003 | 최근 기록 | 최근 변환 N건 조회, 결과 파일 위치 열기, 기록 삭제 | empty / list |

> SCR-002는 별도 화면 또는 SCR-001 위 오버레이/패널로 구현 가능 — 설계 단계에서 결정.

## 주요 플로우 (FLOW-*)
### FLOW-001 · 파일 변환 (핵심 플로우)
```
앱 실행 → SCR-001(empty)
  ─[파일 드롭/선택]→ SCR-001(list: 파일별 포맷 드롭다운, 지원 불가 파일은 사유 표시)
  ─[변환하기]→ SCR-001(converting: 파일별 진행 상태)
      ├─[전체 성공]→ SCR-002(all-success) ─[폴더 열기 / 확인]→ SCR-001(empty)
      ├─[일부 실패]→ SCR-002(partial-fail: 실패 파일 + 사유) ─[확인]→ SCR-001(list, 실패 파일 유지)
      └─[전체 실패]→ SCR-002(all-fail) ─[확인]→ SCR-001(list)
```
- 진입점: 앱 실행 (추후 OS 우클릭 "다음으로 변환" 확장 여지 — Could)
- 분기: 지원하지 않는 확장자 드롭 → 해당 파일만 목록에 비활성 표시 + 사유, 나머지는 정상 진행
- 예외/복구: 변환 중 개별 실패 → 건너뛰고 계속 (REQ-F-009). 변환 중 취소 → 완료된 파일은 유지, 진행 중이던 파일의 불완전 출력물은 삭제
- 이름 충돌: 자동으로 `이름 (1).ext` 부여 (REQ-F-008) — 사용자에게 묻지 않음

### FLOW-002 · 최근 기록 확인
```
SCR-001 ─[기록 아이콘]→ SCR-003(list)
  ├─[항목 클릭]→ OS 파일 탐색기에서 결과 파일 위치 열기
  ├─[기록 삭제]→ 확인 → 목록 갱신 (파일은 유지, 기록만 삭제)
  └─[뒤로]→ SCR-001
```

## 네비게이션 스택 전략
| 전환 | 방식 |
|------|------|
| SCR-001 ↔ SCR-003 | 단순 왕복 (모달 또는 사이드 패널) |
| SCR-002 확인 후 | SCR-001로 복귀 — 전체 성공이면 목록 비움, 실패 있으면 실패 파일만 남김 (재시도 용이) |
| 변환 중 앱 종료 시도 | 경고 후 확인 시 취소 처리와 동일 (불완전 출력물 정리) |
