"배포용(복사방지)" 문서는 실패 케이스로 별도 취급하지 않음(TXT·DOCX 양쪽 경로 모두 일반 경로로 정상 처리됨을 확인) | 공공기관 실사용 서식 5건 + hwplib 배포용 샘플 1건, 6/6 TXT·DOCX 성공·인코딩 깨짐 0건 검증(distribution.hwp도 DOCX 성공, 문단 47·표 1). HWP→PDF는 로컬 LibreOffice 부재로 6/6 err.engine_missing — 검증 안 됨을 "품질 낮음"과 혼동하지 않음. err.password 분기는 진짜 암호화 파일 대비 방어적으로만 유지 | 2026-07-29 |
| DEC-012 | LibreOffice 번들 방식 확정: **버전 26.2.5 고정 + 공식 서버 SHA256 검증 후 다운로드 → MSI 관리자 설치(`msiexec /a`)로 시스템 설치·레지스트리 등록 없이 파일만 추출 → `engine/libreoffice/`에 동봉**. CI가 다운로드 캐시(버전+체크섬 키) + 체크섬 검증 + DOCX→PDF·HWP→PDF 전체 파이프라인 스모크(패키징 후에는 `--frozen-exe`로 실제 exe 실행 시 쓰이는 `engine_dir()` 자동 탐색 자체를 환경변수 없이 검증, PDF 내용까지 pdfminer로 확인)를 매 PR마다 게이트로 실행 — **CI 전체 그린 확인 완료** ([실행 기록](https://github.com/jh3779/file-converter/actions/runs/30458685792)) | hwplib 리비전 고정(DEC-007) 및 CI 게이트 승격(PR #2 리뷰) 원칙과 동일하게 적용 — 임의 최신 버전 다운로드 대신 재현 가능한 고정 버전·체크섬. 관리자 설치는 실제 설치·부팅 시 서비스 등록 없이 파일 트리만 얻는 표준 MSI 기능. `office.py`·`hwp.py`는 PR #2부터 이미 `engine_dir()` 기반 자동 탐색을 구현하고 있었음(PR #4에 반복 제기된 재리뷰에서 "탐색 못 함"·"PR 게이트 미실행" 지적이 있었으나, 현재 커밋·실제 CI 실행 기록으로 직접 반증됨 — 다만 스모크가 자동 탐색 자체를 검증하지 않고 항상 환경변수로 우회하던 것은 그 안의 유효한 지적이라 `--frozen-exe` 시뮬레이션으로 보강, CI에서 실제 통과 확인). 이 과정에서 진짜 결함 하나를 CI로 발견해 수정: JVM 사이드카에 한글 경로("표.hwp")를 그대로 넘기면 영어 로캘 Windows(en-US 러너)에서 `sun.jnu.encoding` 문제로 `?`로 깨져 실패 — ASCII 별칭 경로 우회로 근본 수정, 이후 재실행 통과. 알려진 잔여 제약: 완전 클린 Windows(VC++ 런타임 전무)에서의 동작은 미검증 — 실기기 검증 권장 | 2026-07-29 |
