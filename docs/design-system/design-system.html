F-01디자인 원칙00_project_brief · REQ-NF-006·007
lock금고처럼 — 오프라인을 보이게
핵심 가치는 "파일이 PC 밖으로 나가지 않는다". 이 사실을 UI에 명시적으로 보여준다(기록 화면의 로컬 저장 안내 등). 네트워크가 필요해 보이는 어떤 표현(클라우드 아이콘, 업로드 문구)도 쓰지 않는다.
REQ-NF-002·003
counter_33클릭 완결
파일 넣기 → 포맷 선택 → 변환하기. 이 경로 위에 어떤 화면·다이얼로그도 추가하지 않는다. 저장 위치도 묻지 않는다(원본 폴더 고정, DEC-004). 설명서 없이 쓸 수 있어야 한다.
REQ-NF-006 · DEC-006
shield원본은 신성불가침
원본을 덮어쓰는 UI 경로 자체가 없다. 이름 충돌은 말없이 자동 리네임하고 결과에 표시만 한다. "덮어쓸까요?" 류의 질문은 금지 — 질문이 존재한다는 것 자체가 원본이 위험하다는 신호다.
REQ-F-008 · INV-01·05
fact_check정직한 상태
완료 전 성공 선표시 금지, 가짜 진행률 금지. 실패는 실패라고 말하고 사람이 읽을 수 있는 사유와 재시도 경로를 준다. 일부 실패는 숨기지 않고 요약에 병기한다.
REQ-F-009 · INV-02·03
palette색은 역할로만
primary(청록)는 진행·주요 행동, tertiary(녹색)는 "변환 완료" 한 가지 의미에만 쓴다. error는 실패·파괴 행동 전용. 상태는 색+아이콘+텍스트로 이중·삼중 부호화한다(색 단독 금지).
F-03 · P-02
person비개발자 언어
1차 사용자는 비개발자 일반인. 에러 코드·스택트레이스·기술 용어를 노출하지 않는다. "인코딩" 대신 "한글이 깨지지 않게", "파싱 실패" 대신 "파일을 읽을 수 없습니다"라고 쓴다.

F-02ColorScheme — "Vault Teal"M3 tonal targets · Light/Dark 명시 정의
청록(teal)은 신뢰·보안의 브랜드 축. 아래 스와치는 현재 테마 기준(우상단 토글로 Light/Dark 확인). 구현 시 이 HEX를 그대로 쓴다 — 자동 생성(fromSeed류)에 의존하지 않는다.

secondaryL #4A6365 · D #B1CBCD

tertiary — 완료 전용L #3B6939 · D #A1D399
errorL #BA1A1A · D #FFB4AB
error-containerL #FFDAD6 · D #93000A
surfaceL #FAFDFC · D #101414

역할 규칙: primary = 변환하기 버튼·진행 표시·링크 · secondary = 보조 배지(대기) · tertiary = 완료 상태만 · error = 실패 상태 + 파괴 행동(기록 삭제) · surface 계열 = 배경/카드.

F-06모션최소·기능적
· 변환 중 스피너: 0.9s 등속 회전. 진행률을 알 수 없는 개별 파일 변환에 사용.
· 전체 진행 바: 완료 파일 수 / 전체 파일 수 기반의 실제 값만. 시간 추정 가짜 진행 금지(INV 원칙).
· 드롭존 활성: 드래그 진입 시 배경 primary-container·테두리 primary로 120ms 전환.
· 화면 전환 애니메이션 없음(단일 창 앱). 결과 오버레이는 150ms 페이드만.
